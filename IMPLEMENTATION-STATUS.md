## Implementation Conflicts

**NONE that block Phase 1 work.** Four items are recorded below (items 1 to 3 are Phase 1 items; item 4 is a Stage 2 reference-suite deviation) because the brief's Governing Rule requires surfacing ambiguity rather than silently resolving it — none blocked or required deviation from the locked spec.

1. **Phase-1 deliverable scope vs. §17's phase tables.** The implementation brief requires `README.md`, `profiles/README.md`, `instantiation/README.md`, a `metrics/` seam, and all eleven templates as Phase-1 deliverables. The locked spec's build-sequence table (§17, Phase 1 row) does not name the first four items, while its Phase 2 row separately schedules the evidence-pack and exemption templates even though the Phase 1 row says `templates` without qualification. This is not a contradiction: §14.1 establishes the full repository structure and the brief explicitly resolves the template timing. Nothing in §17 forbids schema-only scaffolding ahead of the phase that activates it, provided no later-phase control is presented as operational. **Resolution:** implemented as the brief instructed. Stubs and the two early templates are explicitly non-operational until their scheduled phases. Flagged here because it is a real scope/timing difference between the two source documents.
2. **`[REQ]`/`[R]` tagging.** The brief's Implementation Quality Rules ask to "use `REQ` and `R` consistently with the locked design." The locked spec uses these tags to distinguish a structural requirement from a recommendation *during architecture design*, when alternatives were still live. Phase 1 implements only resolved, locked decisions (§16, D1–D11 all resolved) — there are no live alternatives left to mark as optional at the implementation layer. **Resolution:** implementation documents state every rule as binding (normative "must/never/required" language) without reproducing `[REQ]`/`[R]` tags; no rule in `KERNEL.md`, `core/`, or `modes/` was downgraded to advisory in the process. Flagged here as an interpretive choice rather than left implicit.
